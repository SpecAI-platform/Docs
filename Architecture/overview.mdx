SpecAI is built as a **single monorepo** containing 12 independently deployable services plus a browser extension, following an **API Gateway \+ microservices** pattern.

## The core idea

Each service owns a single slice of responsibility and communicates either through the **API Gateway** (for client-facing requests) or via **direct internal HTTP** (for service-to-service calls, authenticated with a shared secret header).

## Monorepo structure

```text
SpecAI/
├── apps/
│   ├── web/               # Next.js frontend + API Gateway (BFF)
│   └── extension/         # Browser clipper extension
├── services/
│   ├── core/              # Projects, documents, ingestion routing
│   ├── auth/              # Identity, orgs, RBAC
│   ├── mail/              # Inbound email parsing + outbound notifications
│   ├── jobs/              # Scheduler / queue control plane
│   └── connectors/        # JIRA, Confluence, GitHub adapters
└── services/agents/
    ├── bot/               # Chatbot Agent (Python/FastAPI)
    ├── doc/               # SRS Document Agent (Python/FastAPI)
    ├── scenarios/         # Tester Agent (Python/FastAPI)
    ├── insights/          # Insights Agent (Python/FastAPI)
    ├── jira/              # JIRA Agent (Python/FastAPI)
    └── confluence/        # Confluence Agent (Python/FastAPI)
```

## Tech stack split

| Layer | Language | Framework | Reason |
| --- | --- | --- | --- |
| Frontend \+ Gateway | TypeScript | Next.js (App Router) | Full-stack React, Vercel deployment |
| Backend services | TypeScript | Express | Uniform stack, excellent SDK support for JIRA/Confluence |
| AI agents | Python | FastAPI | Python's AI/LLM ecosystem maturity |

## Request flow

```text
Browser
  └─► apps/web (Next.js server-side route handler)
        ├── Verify JWT (Supabase JWKS, cached in Redis)
        ├── Check RBAC permissions (cached in Redis)
        └─► Internal service (Core / Auth / Agents ...)
              └── Internal secret header (X-Internal-Key)
```

<Tip>
  All backend services are designed to run as **internally-reachable-only** deployments in production. The internal secret adds defense-in-depth but is not the only protection layer — see [Security Model](/architecture/security).
</Tip>
